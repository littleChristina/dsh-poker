# 德州扑克 · 局域网版

和朋友在同一个 Wi-Fi（或 ZeroTier、Tailscale 这类虚拟局域网）里，用浏览器一起玩的德州扑克。

一个 Node 进程同时当游戏服务器和网页服务器：房主在自己电脑上启动，其他人用手机或电脑打开地址就能加入。不用装 App、不用注册账号、不需要数据库，**零第三方依赖**，下载后不用 `npm install`。

- 项目地址：<https://github.com/littleChristina/dsh-poker>
- 环境要求：Node.js 18+，现代浏览器（Chrome / Edge / Firefox / Safari 15+）
- 适用场景：家里、宿舍、朋友聚会等可信局域网；不适合直接暴露到公网

---

## 一、部署：从 GitHub 下载后启动服务

### 1. 安装 Node.js

到 <https://nodejs.org> 下载并安装 **LTS 版本（18 或更高）**。安装完成后打开终端验证：

```bash
node -v
```

能打印出 `v18.x`、`v20.x`、`v22.x` 之类即可。

- Windows：安装时保持默认选项即可，安装后可能需要重新打开命令行窗口。
- macOS：也可以用 `brew install node`。
- Linux：用发行版包管理器，或 NodeSource 的安装脚本。

### 2. 下载代码

用 Git 克隆：

```bash
git clone https://github.com/littleChristina/dsh-poker.git
cd dsh-poker
```

或者打开仓库页面，点 **Code → Download ZIP**，下载后**先解压**，再进入解压出来的目录。不要在压缩包里直接双击启动。

### 3. 启动服务

**Windows：** 双击 `start.bat`。

**macOS / Linux：**

```bash
node server/index.js
```

启动成功后，控制台会打印类似内容：

```
  ♠ ♥ ♦ ♣  德州扑克 · 局域网版
  ----------------------------------------------
  本机：   http://localhost:3000
  局域网： http://192.168.1.10:3000   (WLAN)
  ----------------------------------------------
  日志文件：.../logs/server.log
```

- 自己在这台电脑上打开 `http://localhost:3000`。
- 朋友用「局域网」那一行的地址访问。
- 服务窗口要一直开着；关掉窗口或按 `Ctrl + C`，服务就停了。

### 4. 换端口（可选）

默认端口是 `3000`，被占用时可以换：

```bat
:: Windows cmd
set PORT=4000
node server/index.js
```

```powershell
# Windows PowerShell
$env:PORT=4000
node server/index.js
```

```bash
# macOS / Linux
PORT=4000 node server/index.js
```

换端口后，朋友访问的地址和防火墙规则也要一起改成新端口。

### 5. 放行防火墙

**Windows：** 右键 `scripts/firewall-allow.bat`，选择「以管理员身份运行」。它会添加一条名为 `DSH Poker 3000` 的入站规则。

也可以手动执行（管理员命令提示符）：

```bat
netsh advfirewall firewall add rule name="DSH Poker 3000" dir=in action=allow protocol=TCP localport=3000
```

> 脚本里写死了 3000 端口；如果改了端口，请编辑脚本里的 `localport`，或把上面命令里的端口换成新的。

**macOS：** 系统设置 → 网络 → 防火墙，允许 Node 接收连接（首次运行时系统一般会弹窗询问）。

**Linux：**

```bash
sudo ufw allow 3000/tcp   # 使用 ufw 时
```

放行是否生效，**必须用另一台设备**访问 `http://<你的IP>:3000` 来验证；本机访问 `localhost` 不经过防火墙，验证不了。

### 6. 让朋友加入

**同一个 Wi-Fi：**

1. 查本机局域网 IP：
   - Windows：`ipconfig`
   - macOS / Linux：`ifconfig` 或 `ip addr`
   - 或者直接看启动横幅里的「局域网」地址
2. 朋友手机连同一个路由器，浏览器打开 `http://<你的IP>:3000`。
3. 进入后填昵称，输入房主给的 4 位房间码加入。

**不在同一地点：**

可以用 ZeroTier、Tailscale、Hamachi、Radmin 等工具组一个虚拟局域网。各方加入同一个虚拟网络后，启动横幅会多出「虚拟网卡」地址，朋友用那个地址访问即可，例如：

```
局域网： http://100.95.35.58:3000   (Tailscale · 虚拟网卡)
```

**连不上时依次检查：**

1. 服务是否还在运行，控制台有没有报错；
2. 两台设备是否在同一网段 / 同一虚拟网络（互相 `ping` 一下）；
3. 服务端防火墙是否放行；
4. 手机是否连在「访客网络」（访客网络通常隔离设备）；
5. 学校、公司网络可能禁止设备互访。

### 7. 后台运行（可选）

- **Windows：** 可以用「任务计划程序」开机启动 `node server/index.js`，或在 PowerShell 里：
  ```powershell
  Start-Process node -ArgumentList "server/index.js" -WorkingDirectory "C:\path\to\dsh-poker" -WindowStyle Hidden
  ```
- **Linux：** `nohup node server/index.js > logs/run.log 2>&1 &`，或用 systemd 写成服务。

后台运行时注意查看 `logs/server.log` 确认是否启动成功。

### 8. 启动排错

| 现象 | 原因 / 处理 |
| --- | --- |
| `node` 不是内部或外部命令 | Node 没装好，或安装后没重开终端 |
| 提示版本过低 | Node 低于 18，升级到 LTS |
| `EADDRINUSE` | 端口被占用，按第 4 节换端口，或结束占用进程 |
| 本机能开、朋友打不开 | 防火墙未放行，或不在同一网段（见第 5、6 节） |
| 页面一直转圈 | 服务没启动成功，或地址/端口写错 |

## 二、进入网页后怎么玩

### 1. 大厅

- 填一个昵称，点「创建房间」，成为房主。
- 或者输入朋友给的 **4 位房间码**，点「加入房间」。
- 昵称会记在浏览器里，下次不用重填。
- 创建房间时可以勾选「观战人可见底牌」，决定牌局中途加入的观战者能否看到所有人的底牌（默认关闭）。

### 2. 等待区

- 房主点「邀请」可以复制房间码和局域网地址，发给朋友。
- 房主可以修改本局设置：小盲、大盲、初始筹码、行动思考时间，可选的升盲方式（关闭 / 每 N 手 / 每 N 分钟，倍率 1.25、1.5、2），以及「观战人可见底牌」开关。
- 升盲只在下一手开始时生效，不会中途改掉正在进行的下注。
- 设置面板里改完要记得点「保存设置」才会提交；创建房间时勾选的开关是立即生效的。
- 其他玩家点「准备 / 取消准备」。
- 至少 2 人、且除房主外所有人都准备后，房主才能点「开始牌局」；否则按钮会提示缺什么。
- 每个玩家有一个座位号（1–8），牌桌上的位置按座位排。
- 牌局进行中也能用房间码加入：此时加入的是**观战者**，不占座、没有筹码、不能行动，只负责看牌。观战者能不能看到所有人的底牌，由房主的「观战人可见底牌」开关决定（等待区可改，开局后固定）。

### 3. 牌桌

- **自己永远在正下方**，其他人按座位顺序顺时针排开，所以每个人看到的牌桌方向不同但顺序一致。
- 牌桌顶部显示第几手、当前盲注；开启升盲时还会显示「再 X 手升到 A / B」或「m:ss 后升到 A / B」。
- 顶部右侧的「筹码：数值 / BB」按钮可以切换**整个牌桌的金额显示**：数值（2000）或以当前大盲为 1 BB 的倍数（100.00 BB）。会一起切换自己的筹码、所有人的下注、底池、行动按钮金额、结算金额和座位上的动作文字；盲注设置本身仍用数值显示。偏好会记在浏览器里。
- 自己底牌正面朝上；别人的底牌是牌背。摊牌时才会亮出参与比牌的玩家底牌。
- 观战者不占座，顶部显示「观战中 · 手牌可见/不可见」；没有行动条和加注条，不会成为庄家或盲注，也看不到自己的底牌。
- 中间显示底池、公共牌和当前街道（翻牌前 / 翻牌 / 转牌 / 河牌）。
- 轮到你时底部出现行动条：
  - **弃牌、过牌**：按当前局面显示；
  - **跟注**：按钮上直接写要跟的金额；筹码不够时是「跟注全下」；
  - **加注**：桌面端在牌桌右侧出现竖向加注条，上下拖动或按 `↑` / `↓` 微调，顶部是「全下」、底部是「最小」；手机和窄窗口仍用底部横条滑块。选好「加注到」的总额再确认；如果只能全下，按钮直接变成「全下 X」。
- 行动条上方有倒计时，超时会自动「能过牌则过牌，否则弃牌」。
- 掉线的玩家由服务器托管：等待 3 秒后自动过牌/弃牌，不会卡住整桌。

### 4. 断线与重连

- 页面用 SSE 接收状态，网络抖动会自动重连。
- 刷新页面、手机锁屏后再打开，会自动回到原座位，底牌和筹码不丢。
- 会话 token 存在浏览器 localStorage 里；清理浏览器数据后需要重新加入。
- 服务器重启后房间会消失，需要重新创建。

### 5. 结算展示（9 秒：先亮牌 5 秒，再结算 4 秒）

每手结束后**先不挡牌桌**：桌面保持约 5 秒，用金色边框高亮赢家组合用到的牌（赢家底牌 + 参与的公共牌），方便大家先看清是哪几张牌赢的。

之后剩下约 4 秒弹出结算面板，然后自动开始下一手：

- 赢家、赢得金额、牌型；
- **赢家获胜的 5 张牌**会逐张列出；
- 平分底池时显示「平分」标签，各赢家分别列出自己的 5 张牌；
- 没被跟注而退回的筹码显示为「退回 X」，不计入赢钱。

### 6. 牌局结束与离开

- 筹码归零的玩家出局，自动转为观战者，继续看剩下的牌局；只剩一名有筹码的玩家时本局结束，所有人回到等待区（标题显示「牌局结束」），出局者重新成为玩家并把筹码重置为初始值。
- 房主可以再次开局，开局时所有玩家筹码重置为当前设置的初始筹码。
- 点「离开房间」随时可退；牌局进行中离开会先弃牌，本手结束后移除座位。

### 7. 手机使用

- 手机和电脑连同一个 Wi-Fi，直接开浏览器访问地址即可。
- 竖屏、横屏都能用；牌桌和按钮会随屏幕缩放。
- 建议把页面加到主屏幕，方便下次打开。

## 三、发牌与比牌用的是什么算法

### 1. 牌的表示

一副牌是 0–51 的整数，一副牌只存 52 个数字：

- `rank = card % 13`：0 是 2，1 是 3，……，12 是 A；
- `suit = card / 13`：0 黑桃 ♠、1 红桃 ♥、2 方块 ♦、3 梅花 ♣。

例如 `2♠ = 0`，`A♣ = 51`。这样牌的大小比较和去重都只是整数运算。

### 2. 洗牌：Fisher–Yates

每手牌开始时新建一副有序牌，然后用 **Fisher–Yates（Knuth shuffle）** 打乱：

```js
function shuffle(deck, rand = Math.random) {
  for (let i = deck.length - 1; i > 0; i--) {
    const j = Math.floor(rand() * (i + 1));
    [deck[i], deck[j]] = [deck[j], deck[i]];
  }
  return deck;
}
```

- 从后往前遍历，每次和前面（含自己）的随机一张交换，保证 52! 种排列等概率。
- 随机数用 `Math.random()`（V8 的 xorshift128+ 实现）。它**不是密码学安全随机数**，但用于朋友之间、不涉及真钱的牌局足够；如果想更强，可以把 `rand` 换成 `crypto.randomInt`。
- 每手只洗一次，之后发牌、发公共牌都从这副牌堆顶取。

### 3. 发牌流程

1. 洗好一副 52 张牌。
2. 按座位顺序，轮流给每位玩家发一张，共发两轮（每人 2 张底牌）——和真人发牌一样是一张一张轮着发，不是一次发两张。
3. 翻牌发 3 张、转牌发 1 张、河牌发 1 张，都从牌堆顶取。
4. **不烧牌**（简化实现，不影响公平性）。
5. 公共牌之间留了约 800ms 的间隔，方便看清街道推进。

### 4. 服务端权威与隐藏信息

- 牌只在服务器内存里，客户端**永远不会**收到别人的底牌。
- 每个玩家收到的是「按自己视角生成的状态」：`you.cards` 是自己的两张牌，其他座位的 `cards` 是 `null`；摊牌后才按结算结果公开。
- 客户端只能提交「弃牌 / 过牌 / 跟注 / 加注到多少」这类操作，合法性全部由服务器校验，改前端代码也看不到别人的牌。

### 5. 比牌

- 每人 2 张底牌 + 5 张公共牌 = 7 张，枚举其中所有 5 张组合，共 **C(7,5) = 21 种**。
- 每种 5 张组合先判定牌型（高牌 → 一对 → 两对 → 三条 → 顺子 → 同花 → 葫芦 → 四条 → 同花顺），再把「牌型 + 关键点数」编码成一个整数分值，21 个分值取最大。
- 顺子处理 A2345（A 当 1）和 TJQKA；同花顺里 TJQKA 显示为「皇家同花顺」。
- 同分即平局：每个底池单独取最高分，同分者平分；除不尽的零头从按钮下家开始一人补 1 个筹码，不会凭空多出或消失筹码。
- 多人全下时按投入额分层建主池/边池；只有一个人投入最多时，超出第二名的部分原样退回。

### 6. 盲注与按钮

- 每手结束按钮移到下一个有人的座位；盲注跟着按钮走。
- 两人单挑时，按钮位兼小盲：翻牌前小盲先行动，翻牌后大盲先行动。
- 三人及以上：翻牌前从大盲下家开始，翻牌后从按钮下家开始。
- 短筹码全下不足一个完整加注时，不重新打开加注权（已行动的玩家只能跟注或弃牌）。

### 7. 升盲（可选）

- 模式三选一：关闭、按手数、按时间，两种升盲不能同时开启。
- 按手数：每 N 手升一级（N = 1–50，默认 10）；按时间：每 N 分钟升一级（N = 1–120，默认 10）。
- 倍率 1.25 / 1.5 / 2，默认 1.5。新小盲 = max(旧小盲 + 1, 旧小盲 × 倍率 取整到 5)，大盲恒为小盲的 2 倍，大盲封顶 200000。
- 第 1 级沿用房间设置里的大小盲；升级只在新一手发牌前发生，翻牌、结算和断线托管期间都不会改。
- 时间模式从开局起连续计时；跨过多个级别时直接采用最新级别，日志会记「连升 N 级」。
- 只能由房主在等待区修改；牌局进行中不能改。

### 8. 观战与出局

- 牌局进行中（`playing` / `handover`）用房间码加入的人成为观战者：不占座、没有筹码、不能准备或行动，也不参与庄家和盲注轮转。
- 观战者默认只看到公共牌；房主在创建房间时勾选「观战人可见底牌」，或在等待区设置里打开并保存后，观战者能看到所有在座玩家的底牌。
- 观战者不能看到自己的底牌（因为没有手牌），顶部会显示「观战中 · 手牌可见/不可见」。
- 筹码归零的玩家在下一手开始前转为观战者，继续观看；整局只剩一名有筹码的玩家时牌局结束，回到等待区，出局者自动恢复为玩家、筹码重置为当前设置的初始筹码。
- 等待区加入的仍然是普通玩家，可以点准备；只有牌局进行中加入的才是观战者。

### 2. 默认参数

| 项目 | 默认值 | 可设置范围 |
| --- | --- | --- |
| 座位数 | 8 | 固定 |
| 小盲 | 10 | 1 – 100000 |
| 大盲 | 20 | 2 – 200000，且必须大于小盲 |
| 初始筹码 | 2000 | 100 – 1000000，且至少为大盲的 10 倍 |
| 行动时间 | 30 秒 | 5 – 120 秒 |
| 升盲模式 | 关闭 | 关闭 / 按手数 / 按时间（互斥） |
| 升盲间隔（手） | 10 手 | 1 – 50 手 |
| 升盲间隔（时） | 10 分钟 | 1 – 120 分钟 |
| 升盲倍率 | 1.5 | 1.25 / 1.5 / 2 |
| 大盲上限 | 200000 | 升盲到顶后不再增加 |
| 观战人可见底牌 | 关闭 | 开 / 关（创建房间时勾选，或房主在等待区设置并保存） |
| 结算展示 | 9 秒 | 固定：桌面高亮 5 秒 + 结算面板 4 秒 |
| 房间码 | 4 位 | 去掉 I、O、0、1 等易混字符 |

### 3. HTTP / SSE 接口（开发用）

| 方法 | 路径 | 请求体 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/create` | `{name, spectatorCards?}` | 创建房间，返回 `{code, token, playerId, state}`；`spectatorCards` 控制观战者能否看底牌 |
| POST | `/api/join` | `{code, name}` | 用房间码加入；牌局进行中加入的是观战者 |
| POST | `/api/rejoin` | `{token}` | 用 token 恢复会话 |
| POST | `/api/ready` | `{token, ready}` | 准备 / 取消准备 |
| POST | `/api/start` | `{token}` | 房主开局 |
| POST | `/api/action` | `{token, action, amount?}` | `fold` / `check` / `call` / `raise`；`amount` 是加注到的总额 |
| POST | `/api/config` | `{token, config}` | 房主在等待区改设置 |
| POST | `/api/leave` | `{token}` | 离开房间 |
| GET | `/api/state?token=` | — | 当前可见状态快照 |
| GET | `/api/info` | — | 端口、网卡地址、房间数、运行时长 |
| GET | `/api/events?token=` | — | SSE 推送，每条 `data: {"type":"state","state":{...}}` |

状态快照里常用的字段：

- `phase`：`waiting` / `playing` / `handover`
- `you`：自己的角色（`player` / `spectator`）、座位、筹码、底牌、`legal`（轮到自己时有哪些合法操作）
- `spectators`：观战者列表（不占座、无筹码）
- `spectatorCards`：观战者是否能看所有人底牌的开关状态
- `players[8]`：每个座位的筹码、下注、弃牌/全下标记、庄/盲标记；别人的底牌是 `null`
- `actorId` + `deadlineIn`：当前行动者与剩余毫秒
- `result`：结算（赢家、牌型、各池、净输赢、退回）
- `log`：本局操作日志

### 4. 自测

引擎单元测试不依赖服务器：

```bash
npm test
```

没有 npm 时：

```bash
node --test --test-isolation=none "test/*.test.js"
```

冒烟脚本会真实创建房间，需要先启动服务：

```bash
node scripts/sse-smoke.js
node scripts/lobby-smoke.js
node scripts/table-smoke.js
node scripts/spectator-smoke.js
```

`table-smoke.js` 会让两个机器人按合法操作打完一手，并校验筹码守恒、亮牌、赢家五张牌、9 秒结算、自动下一手等。`spectator-smoke.js` 校验牌局中加入的是观战者、开关关闭时看不到底牌、打开后能看到全部底牌、观战者不能行动或准备。

### 5. 常见问题

**朋友打不开，但我本机可以？**
先看「连不上时依次检查」。九成是防火墙没放行，或不在同一网段 / 虚拟网络。

**端口被占用（EADDRINUSE）？**
换端口（见一、4），同时放行新端口。

**改了代码但页面没更新？**
按 `Ctrl + F5` 强制刷新；浏览器可能缓存了 CSS/JS。

**刷新页面会掉线吗？**
不会，会自动重连回原座位。清理浏览器数据后需要重新加入。

**重启服务器后房间还在吗？**
不在。房间和筹码都在内存里，重启即清空。

**可以放到公网让异地朋友直接访问吗？**
技术上可以，但不建议裸奔：本项目没有 HTTPS、限流和账号体系。更安全的做法是用 Tailscale / ZeroTier 组网，或在前面加反向代理和访问控制。

### 6. 已知限制

- 没有聊天、音效、战绩统计、账号系统。
- 房间数据不持久化，重启服务器即清空。
- 邀请二维码暂未实现（当前用房间码 + 地址复制）。
- 没有管理后台；看服务状态以控制台和 `logs/server.log` 为准。
- 发牌使用 `Math.random`，不是密码学安全随机数；仅适合朋友间娱乐。

### 7. 安全提醒

- 只在自己信任的局域网 / 虚拟局域网里使用。
- 会话 token 会出现在 SSE 的 URL 里，不要把带 token 的地址发给别人。
- 不要把端口直接映射到公网，除非你清楚风险并加了额外防护。

### 8. 迁移与升级

- 整个目录是自包含的：复制文件夹到另一台设备（`logs/` 可不复制），装好 Node.js ≥18，重新启动即可；路径都相对项目目录解析。
- `start.bat` 和 `firewall-allow.bat` 仅 Windows 需要，其他系统手动放行端口。
- 升级代码：拉取新版本覆盖（保留 `logs/` 不影响），重启服务。
